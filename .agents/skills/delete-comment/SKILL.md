# Delete Comment

Audit non-exempt code comments across the Gond repository (or a scoped file or directory), remove comments that add noise or hide trackable defects, preserve real rationale and exempt comments, shrink the baseline ratchet, and report exact category counts and physical line savings.

Accepts an optional target path argument: `[path]` (one or more files or directories, relative to the repository root or absolute). When omitted, the workflow runs across the entire repository.

Use Bun for every command (`bun`, `bun run`, `bun test`), never `npm` or `npx`. Never use em dashes anywhere in edits, issues, or reports.

## Workflow

### 1. Read repository instructions first

Read `CLAUDE.md` before changing any code. Pay special attention to:

- The comment policy under `## Before a commit`: comments belong only where they say what the code cannot (a non-obvious why, a security invariant, a workaround for someone else's bug, or a spec reference). Names, types, tests, and `CLAUDE.md` hold the rest.
- Copy and tooling rules: Bun for everything (never `npm` or `npx`), and no em dashes anywhere.
- Any package-specific rules in `CLAUDE.md` (or local instruction files in scope) so you do not misclassify an intentional invariant or security comment as a tautology or excuse.

### 2. Understand scope and boundaries

`scripts/comment-lint.ts` enforces one set of boundaries across the audit report, the lint rule, and the physical line estimate. Do not invent separate filters.

**File discovery:** Uses `git ls-files --cached --others --exclude-standard` inside the git repo (filtered to `[path]` when provided and verified on disk), falling back to a recursive directory walk outside git.

**Included files** (source code, tests, scripts, and build, CI, or app config with comment syntax):

- TypeScript and JavaScript: `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs` (parsed with the TypeScript compiler API, including JSX `{/* ... */}` containers)
- Swift: `.swift`
- Kotlin: `.kt`, `.kts`
- Rust: `.rs`
- CSS: `.css`
- HTML: `.html`, `.htm` (including embedded `<script>` and `<style>` blocks)
- XML: `.xml`
- Shell: `.sh`, `.bash`
- YAML: `.yml`, `.yaml` (including shell comments inside `run:` block scalars)
- TOML: `.toml`
- JSONC: `.jsonc`
- Dockerfile: `Dockerfile`, `*.Dockerfile`, `Dockerfile.*`
- ProGuard and Gradle properties: `.pro`, `.properties`

**Excluded generated and vendored code** (defined in `scripts/comments/discover.ts`):

- Directory segments: `node_modules/`, `.git/`, `.next/`, `out/`, `dist/`, `build/`, `target/`, `DerivedData/`, `Gond.xcodeproj/`, `.kotlin/`, `.wrangler/`, `coverage/`
- Directory prefixes: `packages/box/test/artifacts/`, `apps/desktop/src-tauri/gen/`, `apps/desktop/src-tauri/permissions/autogenerated/`, `apps/desktop/src-tauri/icons/`, `apps/desktop/src/fonts/`, `.agents/skills/`
- Individual files: `apps/web/next-env.d.ts`, `apps/web/AGENTS.md`, `packages/shared/brand/gond-mark.svg`, `apps/desktop/src/logo.svg`, `apps/desktop/src/team.svg`, `apps/ios/AppIcon.icon/Assets/cog.svg`, `bun.lock`, `apps/desktop/src-tauri/Cargo.lock`
- Generated-file header rule: any file with a parsed comment in lines 1 to 10 matching `/@generated\b|code generated by|do not edit|auto-generated|this file is automatically generated/i`
- Non-code or comment-free formats not scanned: `.md`, `.txt`, `.json`, `.svg`, `.gitignore`, `.dockerignore`, `.env.example`, `LICENSE`, and binaries

**Exempt comments preserved automatically** (defined in `scripts/comments/exempt.ts`, never audited for deletion and never added to the baseline):

- `license`: comments containing `SPDX-License-Identifier:` or `SPDX-FileCopyrightText:`, or top-of-file comments (before any code) containing license or copyright prose (`copyright`, `licensed under`, `mit license`, `apache license`, `open font license`, `permission is hereby granted`, `all rights reserved`, `mozilla public license`, `gnu general public license`).
- `directive`:
  - Line-1 shebangs (`#!`)
  - Dockerfile parser directives before the first instruction (`syntax=`, `escape=`, `check=`)
  - TypeScript triple-slash references (`/// <reference ... />`), `@ts-expect-error`, `@ts-ignore`, `@ts-nocheck`, `@ts-check`, and JSX pragmas (`@jsx`, `@jsxImportSource`, `@jsxFrag`, `@jsxRuntime`)
  - ESLint directives (`eslint-disable`, `eslint-disable-next-line`, `eslint-disable-line`, `eslint-enable`, and block `/* eslint ... */`, `/* global ... */`, `/* exported ... */`)
  - Formatter, linter, bundler, coverage, and editor directives (`prettier-ignore`, `prettier-ignore-start`, `prettier-ignore-end`, `biome-ignore`, `oxlint-disable`, `oxlint-disable-next-line`, `oxlint-disable-line`, `stylelint-disable`, `stylelint-disable-next-line`, `stylelint-disable-line`, `stylelint-enable`, `ktlint-disable`, `ktlint-enable`, `swiftlint:`, `swift-format-ignore`, `swift-format-ignore-file`, `shellcheck `, `yamllint `, `yaml-language-server:`, `noinspection`, `#__PURE__`, `@__PURE__`, `#__NO_SIDE_EFFECTS__`, `@__NO_SIDE_EFFECTS__`, `@vite-ignore`, `webpackChunkName:`, `webpackIgnore:`, `webpackMode:`, `webpackPreload:`, `webpackPrefetch:`, `istanbul ignore`, `c8 ignore`, `v8 ignore`, `#region`, `#endregion`)
  - Swift Xcode jump-bar landmarks (`// MARK:`)
- `api-doc`: explicit `@openapi` or `@swagger` annotations, and Rust doc comments (`///`, `//!`, `/**`, `/*!`) only when the file or its crate's `src/lib.rs` or `src/main.rs` enables `#![warn(missing_docs)]` or `#![deny(missing_docs)]`. Regular `/** ... */` and `///` comments elsewhere are not auto-exempted and are audited on their merits.

Consecutive standalone single-line comments with the same indentation column, prefix, and language (excluding directives) are grouped as one logical comment. Directives are never merged with adjacent non-exempt comments.

### 3. Scan before editing

Run the scanner on the target scope (or full repo when `[path]` is omitted) to capture the pre-cleanup inventory and baseline line estimate:

```sh
bun scripts/comment-lint.ts --report [path]
bun scripts/comment-lint.ts --report-json [path]
```

Record these pre-cleanup numbers before editing any file:

- `filesScanned` and `filesSkippedGenerated`
- `exemptCount` and `exemptByReason` (`license`, `directive`, `api-doc`)
- `nonExemptCount`
- `estimatedTotalLinesSaved`: the exact number of physical source lines that would disappear if every non-exempt comment in scope were removed

The JSON report (`--report-json`) lists every non-exempt logical comment with `file`, `language`, `kind`, `startLine`, `endLine`, `inline`, `physicalLinesSaved`, `hash`, `preview`, and `text`. Use it as your complete checklist so no comment is missed.

### 4. Read surrounding code and classify every non-exempt comment

Never decide from a comment preview alone. Open each file, read the surrounding code (and related tests or callers when needed), and classify every non-exempt logical comment into one of five categories:

| Category | Meaning | Action |
| --- | --- | --- |
| **Tautology** | Repeats what the code, identifier names, types, or control flow already make clear (including decorative section banners or restating obvious steps). | **Delete it.** |
| **Excuse** | Justifies a workaround, hack, or shortcut that leaves a concrete implementation problem in this codebase (not an intentional design tradeoff or an external bug outside Gond's control). | Search existing issues (`gh issue list`), reuse a matching issue or file a new one (`gh issue create`) describing the problem, exact location, and what counts as fixed, then **delete the comment**. If issue filing is unavailable, **retain the comment** and include a ready-to-file issue in the final summary. |
| **Stale** | Describes behavior, paths, constraints, TODOs, or workarounds that no longer apply. | **Verify against the current code**, then **delete it**. |
| **Rationale** | Explains a non-obvious decision, security invariant, external/upstream bug workaround that still applies, ordering constraint, protocol/spec reference, or tradeoff the code cannot express on its own. | **Keep it in place.** |
| **Unclear** | Purpose, accuracy, or necessity cannot be determined confidently from the code and repo context. | **Retain it** and **flag it for review** in the final summary. |

**Editing rules while cleaning up:**

- Leave all exempt comments (`license`, `directive`, `api-doc`) untouched.
- Leave kept `Rationale` and `Unclear` comments verbatim. Rewording a baselined comment changes its content hash, which `comment-lint` treats as deleting one comment and adding an unbaselined one.
- Do not add any new non-exempt comments while cleaning up.
- When deleting a standalone comment (including a standalone JSX `{/* ... */}` expression container), remove the entire line(s) cleanly and avoid leaving redundant consecutive blank lines.
- When deleting an inline comment on a code line, strip trailing spaces left before the newline and keep the code intact.
- For **Excuse** comments, check GitHub first:
  ```sh
  gh issue list --state open --search "<keywords>"
  gh issue create --title "<short sentence-case title>" --body "<problem, file:line and symbol, what counts as fixed>"
  ```
  If `gh` is unavailable, unauthenticated, offline, or cannot create issues in this repository, do not delete the excuse comment; keep it in place and emit a ready-to-file issue in the summary.

### 5. Shrink the baseline ratchet

After deleting comments, re-run the scanner on the same scope to confirm the post-cleanup counts and line savings, then ratchet `scripts/comment-baseline.json`:

```sh
bun scripts/comment-lint.ts --report [path]
bun run lint:comments -- --update [path]
```

Omit `[path]` when auditing the full repository (`bun run lint:comments -- --update`).

**How the lint rule and baseline ratchet work:**

- `scripts/comment-baseline.json` records a deterministic per-file multiset of `{ hash, preview }` entries for baselined non-exempt comments (`hash` is the first 16 hex characters of SHA-256 over `${kind}\0${normalizedText}`, where `\r\n` is normalized to `\n`, comment delimiters are stripped, and each line is trimmed).
- Moving an existing baselined comment to another line or changing its indentation within the same file preserves its hash.
- **Blocks new comments:** Check mode (`bun run lint:comments`) fails on any non-exempt comment whose hash is missing from that file's baseline multiset, including duplicate copies of an already baselined comment.
- **Prevents comment swapping:** Deleting a baselined comment and adding a different comment at the same count (in the same file or across files) fails both check mode and `--update`, because the removed hash is flagged as stale and the new hash is flagged as unbaselined.
- **Shrink-only update:** `--update` removes stale baseline entries for deleted comments (and drops file keys whose list becomes empty) and **never** adds new unbaselined comments. If any new unbaselined comment exists, `--update` prints it and exits 1.
- Never use `--write-baseline` during routine cleanup; it exists only for deliberate baseline initialization.

### 6. Run verification checks

Run the repository checks required by `CLAUDE.md`:

```sh
bun run lint
bun run typecheck
bun run test
```

When any file under `apps/web/` changed, also run:

```sh
bun run --filter @gond/web build
```

Note that `bun run lint` runs workspace linters plus `bun scripts/comment-lint.ts` (check mode), verifying that both zero unbaselined comments and zero stale baseline entries remain.

### 7. Report results

Finish with a structured summary containing all four sections below.

**Physical line savings rule:** Count only physical source lines that actually disappear when comments are removed. Removing an inline comment on a line that still contains code saves **0** physical lines. Removing a standalone single-line comment or standalone JSX `{/* ... */}` line saves **1** line; removing a multi-line standalone block saves the number of lines that become empty; removing multiple comments that together vacate a single code-free line saves **1** line total. Compute:

- **Source lines saved by this cleanup:** the exact physical lines removed by the comments you deleted (equal to pre-cleanup `estimatedTotalLinesSaved` minus post-cleanup `estimatedTotalLinesSaved` when only comments were edited, or computed via `countPhysicalLinesSaved` on the deleted comments).
- **Estimated total savings if all non-exempt comments were removed:** the pre-cleanup `estimatedTotalLinesSaved` reported by `bun scripts/comment-lint.ts --report [path]` (and also note the post-cleanup remaining `estimatedTotalLinesSaved` for clarity).

Use this summary format:

```markdown
## Comment Audit Summary

**Scope:** `<full repository | path>` (`<N>` files scanned, `<M>` generated files skipped)

### Comment Counts by Category
- **Tautology (deleted):** `<count>`
- **Excuse (deleted with issue):** `<count>`
- **Excuse (retained, issue filing unavailable):** `<count>`
- **Stale (deleted):** `<count>`
- **Rationale (kept):** `<count>`
- **Unclear / Flagged (retained for review):** `<count>`
- **Exempt (preserved):** `<total>` (license: `<n>`, directive: `<n>`, api-doc: `<n>`)

### Issues Filed or Reused
- `#<number>` (<filed | reused>): `<title>` (`<file:line>`)
(Or, if issue filing was unavailable, list each ready-to-file issue with title, location, problem, and what counts as fixed.)

### Comments Flagged for Review
- `<file:line>`: `<short quote>` (reason it is unclear)

### Physical Line Savings
- **Source lines saved by this cleanup:** `<deleted physical lines>` (counting only physical lines that disappeared; inline comments removed from code lines save 0)
- **Estimated total savings if all non-exempt comments were removed (pre-cleanup):** `<pre-cleanup estimatedTotalLinesSaved>` (`<post-cleanup estimatedTotalLinesSaved>` remaining across kept non-exempt comments)

### Verification
- `bun run lint:comments -- --update [path]`: `<stale entries removed>`
- `bun run lint`: pass
- `bun run typecheck`: pass
- `bun run test`: pass
- `bun run --filter @gond/web build`: `<pass | skipped (no apps/web changes)>`
```
